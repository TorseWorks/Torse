# 持久化

包名：`torse-storage`。提供有界日志、检查点发布与读取、恢复扫描和故障处理。本目录测试验证存储容器行为，真实世界与执行状态的持久装配已接入[服务端](../../apps/server/README.md)，使用对应的WorldCodec或ExecutionCodec。

| 文件 | 职责与状态 |
|---|---|
| [journal.rs](src/journal.rs) | CommitJournal、预留令牌、有界队列、文件创建与重开 |
| [backend.rs](src/backend.rs) | 有界内存后端、文件后端、可注入失败的追加与同步接口 |
| [recovery.rs](src/recovery.rs) | 逐条验证包裹、载荷、世界、兼容信息与连续提交位置 |
| [checkpoint.rs](src/checkpoint.rs) | CheckpointStore、发布状态机、读取与显式清理 |
| [checkpoint_backend.rs](src/checkpoint_backend.rs) | 内存与文件检查点后端、独立同步边界和故障注入接口 |
| [manifest.rs](src/manifest.rs) | 固定宽度manifest编码、完整前缀校验与位置检查 |
| [segments.rs](src/segments.rs) | 日志分段、持久保留点、只读扫描与段容量 |

## 日志行为

`MemoryJournal`与`FileJournal`共用`Journal`状态机。初始化显式传入Binding、可信检查点位置、具体StorageCodec和JournalConfig，不提供无界默认值。内存后端另设累计保留字节上限，超限按存储失败处理；其同步结果仅表示当前进程内可读取的完整前缀。

`try_stage`检查世界、兼容信息和下一序号，完成有界编码，预留条目与帧字节容量。一次只允许一个未消费令牌，与契约中的单准备项一致。Staged不可复制，内部绑定实例、Binding和位置；丢弃释放容量，序号可重试。

`accept`只移动已经预留的缓冲。队列槽位在构造时分配，接纳不进行编码、I/O或队列扩容。错误实例或旧实例令牌属于终止性故障。宿主必须在权威世界发布后立即接纳令牌，并在`flush_through`成功后才公开对应结果。

`flush_through`按顺序写到目标位置，再执行同步屏障。文件后端使用`write_all`与`sync_all`。任一失败后停止实例，保留此前DurableSeq，释放待写缓冲；后续操作失败，必须通过新实例恢复。目标未被接纳或属于其他世界时返回输入错误。

## 容量与恢复

JournalConfig同时限制待写条目数、帧总字节、单记录编码预算和帧载荷上限。单记录无法放入空队列时返回TooLarge；暂时被其他记录占用时返回Busy。编码期间另有至多两个受单记录上限约束的缓冲，字节限额按有效数据长度计算，分配器开销另计。

`scan_journal`逐条读取完整帧后解码，通过回调交给独立恢复构建器。回调接收到坏记录前的完整前缀，后续任意失败时调用方丢弃整个构建器。扫描限制单帧和单条解码分配，总世界预算由领域恢复构建器控制。

扫描结果包含最终位置、有效字节数、完整记录数和不完整尾部标记。跳号、重复、完整记录损坏、错误世界和兼容不符均失败，错误包含字节偏移。文件重开先扫描，只有扫描成功后才截去不完整尾部，同步有效前缀，再继续追加；损坏或预算不足时保持文件内容。

文件实例持有排他文件锁，创建采用`create_new`，避免覆盖既有日志。[服务端](../../apps/server/README.md)持有世界目录锁。首次回收前保持原单文件布局；首次回收会发布独立的分段保留点，后续追加写入有界段文件。初始空日志及已有世界根目录中的目录项由服务端生命周期同步，上级根目录的首次持久发布仍由宿主负责。

日志、检查点manifest与世界目录的锁所属对象在Drop时显式unlock。复制或子进程继承的描述符可能比原对象存活更久，单独关闭原描述符不能保证锁立即释放。日志重开和目录校验的错误路径也保留解锁守卫。三项回归测试在保留描述符副本的条件下验证重新加锁，并确认新持有者仍能阻止第三方进入。

## 检查点发布

`Checkpoints<M, C, B>`实现契约中的`CheckpointStore`，提供MemoryCheckpoints与FileCheckpoints别名。配置必须显式限制领域编码与解码预算、帧大小、manifest总字节和快照文件数。内存后端另有累计保留字节上限。

宿主在Tick边界暂停，先把日志同步到快照位置C，再捕获完整有限世界，传入同一Binding的Durability。存储检查世界、兼容信息、运行代数、`C <= DurableSeq`和位置不回退；首次发布必须为位置0。世界捕获是否完整及ResumePoint是否为Tick边界由领域层与宿主负责，通用存储保留阶段和步骤原值。

发布顺序为编码及解码预检、创建新一代快照、同步快照、读回验证包裹与领域元数据、追加manifest记录、同步manifest，最后更新当前检查点。发布不修改旧快照。开始写入后的任何失败都会停止实例，必须重开；失败可能留下孤立快照、半条manifest或完整的新manifest。

文件后端接收已存在的专用目录，持有manifest及稳定的命名空间排他锁。快照使用`create_new`，manifest追加发布，整理时原子替换，完整布局见[FORMAT.md](FORMAT.md)。重开先检查完整manifest前缀和最新引用的快照，成功后才截去不完整尾部并同步。完整损坏、快照缺失及元数据不符均报错，保留原文件，不自动选择旧检查点。孤立文件的代号会被跳过，避免重用。`FileCheckpointBackend::inspect`不会创建锁文件，旧目录在成功激活时补建稳定锁。

`Checkpoints::inspect`与`activate`用于分离只读检查和尾部修复。inspect允许读取当前快照，禁止发布与清理；宿主完成独立领域恢复后才activate，修复不完整尾部并同步。activate失败停止实例，重复成功激活不产生额外操作。open完成检查与激活两步，适用于由调用方直接完成存储恢复的场景。

## 保留与清理

`prune(retain)`单独执行，至少保留一代。它验证所有拟保留快照，按manifest代号与提交位置选择最近的已发布快照，先同步并原子发布精简的manifest，再删除更旧快照和未发布的孤立文件。替换前后中断分别保留旧根或新根，删除中断只留下可重试的孤立文件。清理失败停止实例，当前快照始终保留。目录只接受约定名称的普通文件，其他文件会触发错误。

返回的`log_floor`是实际保留检查点中的最早提交位置。宿主将它交给`CommitJournal::reclaim`，先持久发布保留点，再删除结束位置不晚于它的完整段；相交段保留。被完全覆盖的旧单文件缩为格式标记，排他锁仍使用同一文件。首次转换之后，`max_segment_bytes`与`max_segment_files`限制段大小及文件数。当前活动段可以继续追加，单条记录不能超过段上限。保留点必须属于同一世界、已持久且没有待写记录或未释放令牌。

`scan_file_journal`同时读取旧日志和分段布局，不修改文件。保留点晚于可信检查点、段跳号、重叠、完整损坏和非末段不完整均拒绝。仅最终段的不完整EOF可在成功恢复后修复。`FileJournal::open_from_checkpoint`接收旧日志基线及可信检查点，`visit_retained`提供有界逐条引用追踪；检查点提供同名快照遍历入口。分区页的领域引用与回收由服务端维护。

manifest记录保存发布时已知的DurableSeq。宿主恢复时须检查检查点与日志至少覆盖该位置，再交给独立构建器完成恢复；manifest发布之后新增的持久提交仍需后续生命周期记录其恢复预期。整理释放manifest容量，但保留快照加新发布记录仍须放入显式上限，容量不足时继续拒绝发布。

## 验证边界

[日志测试](tests/journal.rs)覆盖内存与真实文件行为、预留释放、容量、令牌误用、逐字节部分写入和刷盘失败。[恢复测试](tests/recovery.rs)覆盖截断、位翻转、跳号、插入删除、碎片读取、I/O失败、预算、未知字节往返及重开失败保留原文件。

[检查点测试](tests/checkpoint.rs)覆盖发布顺序、固定字段布局、位置与身份错误、容量、逐字节manifest尾部截断及部分追加、完整损坏、快照缺失、保留与清理、同步失败和五个实际子进程退出边界。本crate使用测试模型组合检查点与日志后缀；真实世界恢复、续号与进程退出验证位于[服务端测试](../../apps/server/tests/world.rs)。

现有CI在Linux和Windows执行存储及服务端测试，文件锁修复与平台验证见[回归记录](../../benchmarks/archive/persistence/M3-file-locks.md)。文件屏障调用`sync_all`，Unix实现另同步目录；进程退出验证不等于硬件断电保证，具体文件系统的目录项持久性仍需平台验收。内存后端仅保证进程内可读。世界目录锁、初始数据文件同步和真实领域恢复已由服务端装配，上级根目录的首次持久发布仍由调用方负责。
