# 离线运行时表

`cook`把CompiledContent、PNG身份及解析后的语言映射转换为经过校验的运行时行。基础内容的生成命令在仓库根目录执行：

```sh
cargo run -p torse-tools --locked -- cook-base games/base/assets .work/base.tcook
```

games/base/assets/cook.toml分配稳定图片GUID，并列出源路径和语言标签。命令采用与当前基础客户端相同的内容、方块动作和库存注册，校验PNG解码与语言文件语法，再通过临时文件替换输出。输入非法时保留原输出。

源路径必须位于素材包内，每个作者文件最多8MiB，解码后RGBA像素最多64MiB。当前入口处理既有基础内容装配，不提供通用TOML方块定义加载器。

## 运行时约定

状态按方块键顺序展开，最后一个有限字段变化最快。每行记录方块键、块内状态索引、字段值、遮挡、面支撑、碰撞、六面材质槽及六面可选覆盖槽。面支撑使用[独立声明](SUPPORT.md)，不从碰撞或遮挡推导。

稠密材质表按ContentKey与AlphaMode排序，同一贴图在不同透明模式下拥有不同槽。图片按GUID排序，语言及消息键按字典顺序排序，输入列表顺序不影响输出字节。

PNG字节保留在外部。图片行包含GUID、源文件SHA-256、内容键别名和相对PNG路径。替换PNG保留GUID，但改变呈现兼容身份。表中不包含解码像素、网格或视觉模型几何；加载器仍需资源目录和PNG文件。当前客户端继续嵌入源文件，默认改读运行时表属于后续接入。

无窗口示例宿主已接入运行时表：

```sh
cargo run -p torse-tools --locked -- run-cooked .work/base.tcook games/base/assets
```

入口通过CookedResources读取状态、材质及语言行，仅打开清单中的PNG，不再读取作者TOML或语言文件。宿主将状态与覆盖材质逐行核对原生注册表，并检查完整编译器摘要。输出包含驻留和峰值计账；释放后remaining_bytes必须为0。可用`--memory-mib N`设置共享预算，默认32MiB。

通用加载器接受有界图片读取回调，先核对源SHA-256和尺寸，再解码为RGBA并装入AssetCatalog。资源及临时编解码分属共享MemoryPool的Resource和Codec类别。初次加载任意图片失败时，整个未发布对象连同收费一起释放；重装失败保留既有资源。具体句柄与依赖约定见[资源说明](../assets/README.md)。

状态行只是遮挡、面支撑、碰撞和材质投影，不能完整替代CompiledContent或BlockStateRegistry。动作定义、发光等信息仍在编译器与注册表中。完整的编译器权威和呈现摘要分别进入对应的运行时表摘要，相关行为变化仍会影响兼容身份。

## 格式版本3

整数和IEEE-754的f32均使用小端编码。字符串先写u16的UTF-8字节长度，再写相应字节；超长字符串报错，不截断。以下计数默认使用u32。

头部为TCOOK003、版本3及四个32字节SHA-256：表权威、表呈现、编译器权威、编译器呈现。四张带计数的表按下列顺序写入。

| 表 | 行布局 |
|---|---|
| 状态 | 方块字符串、u16块内索引、带计数的u16字段值、u8遮挡、u8附着支撑、u8结构支撑、碰撞形状、六个u32材质槽、六个可选覆盖槽 |
| 材质 | 内容键字符串与u8透明模式：0为Opaque，1为Mask，2为Blend |
| 图片 | u128的GUID、32字节源SHA-256、键字符串、路径字符串 |
| 语言 | 语言字符串、带计数的消息键和值字符串对 |

两个支撑掩码均只允许六位，按-x、+x、-y、+y、-z、+z排列，超过六位拒绝。零表示该类别的六面均不提供支撑。类别固定为Attachment和Structural，不编码任意字符串或回调。可选槽的标签0表示空，标签1后跟u32槽号。碰撞形状的标签如下。

| 标签 | 形状 | 附加字段 |
|---|---|---|
| 0 | 无碰撞 | 无 |
| 1 | FullCube | 无 |
| 2 | LowerSlab | 无 |
| 3 | Panel | 无 |
| 4 | Cross | 无 |
| 5 | Corner | 无 |
| 6 | Stair | 无 |
| 7 | Box | 六个f32，依次为min xyz及max xyz |
| 8 | Compound | u16计数及相应Box序列 |

视觉模型不能用作碰撞形状。边界必须有限且有序；独立Box位于单位格内，Compound的Box允许延伸至[-1,2]，与Shape::validate一致。

权威哈希的域为torse-cooked-authority-v3，覆盖编译器权威摘要及状态身份、字段值、遮挡、面支撑和碰撞。呈现哈希的域保留torse-cooked-presentation-v2，覆盖编译器呈现摘要、状态身份、材质及覆盖槽、材质表、图片和语言表。只改支撑声明不改变呈现摘要。

哈希中的可变字符串使用u64字节长度，可变列表使用u64计数；标量和形状沿用文件编码。这些摘要用于检测损坏和兼容变化，不是可信发布者签名。

当前格式替代TCOOK001版本1和TCOOK002版本2。读取器明确拒绝旧格式，需要从源文件重新生成，不能把缺失字段解释成完整支撑。世界存档和网络布局不变；声明了支撑的内容具有新的权威兼容身份，已有世界仍受兼容检查约束。

## 读写校验

write_cooked返回Result，并校验与read_cooked相同的不变量。读取器拒绝截断、尾随字节、摘要不符、重复或乱序行、非法别名、几何、遮挡位及越界材质引用。每个方块的状态索引从0连续递增，字段元组长度一致且递增。

默认上限为64MiB编码输入、64MiB计账的持有数据，以及一百万个累计条目。计数检查在容量预留前进行，同时检查剩余文件字节。read_cooked_with_limits允许调用者进一步降低上限。

持有数据的计账包含行、字段值、字符串及估算的映射元数据，不代表进程内存的精确上限。内容限制继续适用：状态和材质各最多65535行，每个方块最多4096种状态，每个Compound最多64个Box。

回归测试覆盖基础文件生成的确定性、注册表逐行一致、成功替换与失败保留、摘要分离和字段分隔、所有截断前缀、每字节单比特翻转、巨大计数、资源限制、非法几何、别名、槽位，以及重复的序列化消息键。
