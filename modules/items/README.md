# 物品模块

[20261029]

`torse-items`是可选的官方玩法模块。物品标识、堆叠限制、放置方块关联和破坏产物属于游戏规则；内核只负责通用内容、授权、原子事务、持久化和复制。模块复用`torse-inventory`的受保护槽位，不在世界内核加入背包或具体物品。

## 目录与装配

`Catalog::new`接受稳定的`ItemDefinition`及按方块标识配置的回收物品。物品可以没有放置关联，回收数量可以大于1。重复标识、未知方块、未知产物、零数量及超堆叠限制会被拒绝。目录至多4096项，库存沿用最多64槽的限制。

宿主在编译内容前依次注册方块动作、库存和物品模块，然后构建注册表与目录。绑定`descriptors()`、`handlers(catalog)`和`block_handlers()`；同时绑定库存动作时，必须传入同一目录的`stack_rules()`。`block_handlers()`保护受库存约束的玩家，禁止直接绕过物品结算编辑地形。没有物品使用权限的演员仍遵循宿主显式授予的创作编辑策略。

调用`Catalog::bind_compatibility`一次，将物品成员、数量上限、放置关联和回收规则冻结进兼容身份。目录按稳定内容键排序，运行态方块编号不进入摘要。修改规则必须让旧世界和会话明确拒绝，或先完成显式迁移。编码格式没有改变。

`fixture_catalog`提供石头、玻璃半砖和植物，整块玻璃回收两件半砖。`block_catalog`为简单内容包提供每种方块各一件的通用回收规则。复杂游戏应提供自己的目录。`starter`仅为新建演示玩家提供初始物品；重新连接和恢复不会调用它补货。

## 交互与原子性

| 动作 | 结果 |
|---|---|
| `items:action/place` | 从所选槽消耗1件，并放置或补全方块 |
| `items:action/harvest` | 破坏方块，优先合并同类堆叠，再填空槽 |
| `items:action/swap` | 在同一授权库存内交换两个槽位 |
| `items:action/settle` | 仅供上述放置／回收动作内部调用的库存结算 |

放置和回收通过动作分派器组合两个所有者各自规划的事务：地形由方块模块规划，库存由库存所有者规划。两个子动作观察同一权威快照，发布时一起检查地形读集和库存的精确旧值，只推进一次世界序号。无空间、库存过期、碰撞、未加载、越界或权限不足都会拒绝整个操作，不会先扣物品或先拆方块。

回收产物直接进入背包，放不下时保持原方块；当前模块不生成地面掉落实体。物品耐久、装备、配方和物品使用脚本由后续可选规则装配。

## 权限与保存

请求仅携带数据，`edit_call`和`swap_call`不会发放权限。宿主应把库存实体限制为当前玩家，并授予批准区域中的方块目标。物品使用需`items:permission/use`及`world:permission/edit`；库存结算分别检查`inventory:permission/consume`、`insert`，交换检查`swap`。直接调用结算动作会被拒绝。

库存沿用`inventory:schema/container`的持久组件及授权可见性。联网客户端只能提交请求并等待服务端增量，不预测或修改背包数量。文件服务端保存混合事务日志、回执与快照；重试不会重复扣物品，恢复不会重新运行物品动作。

## 客户端入口

演示客户端提供36槽背包和九格快捷栏，数字键1至9选择，Tab开关物品栏，也可在按键设置中修改。点击来源槽后点击目标槽交换；关闭面板只取消选择，不持有临时物品堆叠。局部世界的库存实体禁用碰撞且不绘制，独立于短暂的行走碰撞体。

联网演示使用`torse-server WORLD --players 1 --editors --fill`建立新世界，再用客户端`--connect 127.0.0.1:7777`连接。宿主只把所分配玩家的库存授予该会话；其他观察者只能看见允许公开的实体信息。认证服务端通过用户策略明确设置实体及权限，不从请求中的库存编号推断所有权。

本地演示世界及其库存随窗口关闭销毁；持久世界由文件服务端保存。真实机器面板仍是单独的预览，不代替背包，也不允许通过UI直接改组件。

## 验证

`cargo test -p torse-items`覆盖半砖消耗与补全回收、空间不足、过期计划和越权路径。服务端`items`集成测试覆盖真实文件恢复、请求去重及授权复制。客户端测试覆盖真实槽位交换、模式切换期间库存稳定，以及三种界面缩放下所有槽位的按下／释放捕获。
