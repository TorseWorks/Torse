## 目标

基线：`329a177`及本文描述的改动。

## 方法

### 接入

新增`torse_server::systems::SystemBinding`及`bind_module_systems`，将CompiledContent中的registered_systems绑定为既有DurableRule。`ExecutionHost::with_modules`和`ExecutionRecovery::with_modules`分别用于创建与恢复，启动前校验内容权威摘要；普通new构造入口仍供已有手工适配使用。

装配先执行模块依赖与服务解析，再核对每个权威系统的身份、所属模块、阶段和处理器。每个服务端或共享系统必须恰好有一个绑定；客户端专属系统不装入权威宿主，也不能满足服务端模块的硬依赖。重复系统、缺失依赖、缺少或多余绑定、阶段不匹配及零输出预算均在调用处理器前拒绝。

同阶段的硬依赖与服务提供者建立系统依赖边，包括没有系统的中间模块所形成的传递依赖。结合处理器的before、after和原优先级排序，检查缺失目标、跨阶段边和循环。装配结果将拓扑顺序写成规范事务优先级，周期任务与定时回调产生的计划都采用这个优先级，避免后续事务仲裁把依赖顺序反转。阶段内部仍读取共同前态，依赖不表示能读取同阶段前一个系统尚未发布的输出。

## 结果

### 预算与来源

声明max_items及max_bytes与宿主运行态上限取较小值。周期调用整批计划、单次定时调用和单次动作通知分别检查冻结任务体或事件列表的线格式条目、编码字节和解码拥有字节；超额输出不进入冻结记录。原生回调返回值在校验前已经构造，该边界限制输出，不是原生代码的内存或CPU沙箱。

通过此入口装配的系统直接产生本模块来源的事务。声明来源与成员来源不一致或返回错误阶段时拒绝。已有跨模块原生业务适配仍可使用原手工DurableRule入口；本次没有新增跨来源授权令牌。事件只能指向已装配的Simulation系统，沿用现有定时事件阶段语义。

绑定后的系统默认串行，未把内部处理器的并行声明直接透传，确保所有输出经过上述校验。已有手工规则的并行规划路径不变。Wasm包自动注册系统、动态热替换及模块生命周期回调不在本次实现范围。

### 持久执行

仍使用原冻结、提交、事件与恢复记录，没有改变快照或日志布局。系统声明和预算已属于内容权威摘要，改变后拒绝用旧兼容身份重开；封存后的SystemSpec由既有运行态恢复核对。未完成冻结任务重启后继续结算，已提交日志只重放结果，不重跑处理器。

### 验证

Windows全工作区626项测试通过，无忽略项；格式、禁止警告的Clippy及Rustdoc检查通过，服务端mods特性的全部目标编译通过。

| 场景 | 结果 |
|---|---|
| 声明或绑定顺序互换 | 封存的系统声明及事务仲裁顺序一致 |
| 消费者回调优先级和任务键都排在提供者之前 | 依赖仍使提供者先提交，消费者的旧值冲突整项拒绝 |
| 依赖经过没有系统的中间模块 | 仍建立到实际提供者系统的依赖 |
| 缺处理器、重复绑定、冒用模块及阶段不匹配 | 启动失败，不调用任何处理器 |
| 缺模块、重复系统、非法阶段、空预算和客户端硬依赖 | 装配拒绝 |
| 调度循环、缺失目标及跨阶段依赖 | 装配拒绝 |
| 周期计划条目过多，周期、定时或动作通知字节超额 | 拒绝输出，世界保持不变 |
| 定时事件提交后重开 | 结果保留，处理器调用数不增加 |
| 系统预算变化后重开 | 兼容核对拒绝，随后仍可用原配置重开原世界 |
| 子进程在Simulation冻结后直接退出 | 重启不重新规划，按依赖顺序完成冻结事务；再次重开不调用处理器 |
