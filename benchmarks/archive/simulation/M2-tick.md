范围：未记录

## 目标

命令内含断言，驱动、仲裁或索引回退时以非零状态退出。

## 方法

### 场景内容

装载两个边长16的分区，生成一个实体并从`(15.5, 2.0, 0.5)`移动到`(16.5, 2.0, 0.5)`，跨越`x = 16`的分区边界。

注册两个系统：`base:first`优先级1，`base:second`优先级5，两者都读取同一空格`(3, 1, 3)`并分别写入石头与玻璃半砖。运行三个Tick：第一个Tick耗时80ms（预算50ms），后两个各20ms。

## 结果

### 输出

```text
ticks=3
committed=1
rejected=1
commit_seq=1
overruns=1
entities=1
moved_section_entities=1
contested_state=6
```

### 判读

- `committed=1`与`rejected=1`：两个系统在同一阶段争用同一格，只有优先级高的提交。
- `commit_seq=1`：Ticks 2与3中空格已被填充，两个系统都不再提出事务；被拒事务不消耗序号。
- `overruns=1`：只有第一个Tick超预算，时钟记录次数但不跳Tick也不改步长。
- `moved_section_entities=1`：实体跨界移动后，目标分区的空间索引能查到它，原分区为0。
- `contested_state=6`：争议格的最终状态是石头，与胜出事务一致。

## 复现

### 运行命令

```sh
cargo run -p torse-tools -- tick-scenario
```

## 边界

### 未覆盖

- 并行执行：驱动按阶段串行运行系统，尚无并行任务与访问依赖调度。
- 阶段可见性：系统读取的是上一阶段提交后的状态，同阶段内看不到彼此事务的中间结果。
- 实体与地形的双向约束：实体不参与碰撞求解，移动合法性与地形碰撞分别验证。
- 组件写入路径：组件校验与存储已有，但尚无事务化的组件修改操作。
