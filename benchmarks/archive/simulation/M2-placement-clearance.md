## 目标

基线：`de9ce4b`及本文描述的改动。

### 问题与行为

原放置动作只在规划时检查实体占用，事务只保存单元旧状态。先规划放置，再执行实体移入时，旧计划仍能把方块放在实体所在位置。

放置动作现在通过Transaction::require_block_clear记录目标位置与最终状态。准备时解析实际状态的碰撞形状，检查事务完成后的实体集合，包括同组移动、生成与销毁；附属方块实例不隐含碰撞体。发生占用冲突时整项拒绝，不修改单元、实体、提交位置或身份分配水位。上半、下半和同格补全沿用各自的实际形状，破坏不要求清空空间。

准备结果保存解析后的形状边界，发布前在任何世界写入之前再次复核。可信宿主若绕过事务在准备后改变占用，发布返回不变量错误，宿主按现有约定停止实例，不能把已经预留日志的准备项当作普通业务拒绝后继续运行。

## 结果

### 冻结与格式

空间条件作为StableCell列表保存稳定内容身份与有限值。FrozenTask的事务标签3表示带空间条件的组，写组身份、成员数，然后逐成员写既有StoredTransaction正文及clearance列表。没有空间条件时沿用标签1或2，既有字节保持不变。旧读取器遇标签3明确拒绝，新读取器继续读取标签0、1、2。

每事务或原子组合计最多256个条件。每个条件必须非空、位置唯一，并对应本成员最终写入的同一状态；未检查的底层原生组若覆盖了目标状态，也会拒绝。编解码和准备均检查边界，解码在分配条件数组前检查累计数量及字节预算。直接以旧StoredTransaction正文编码带条件的成员会报错，避免静默丢失条件。

重启后未执行任务保留空间条件并在准备时重新检查；已结算日志按既定结果恢复，不重新运行碰撞求解。世界载荷布局、Execution提交和快照版本未改动，仅扩展已有冻结事务标签。

### 验证

Windows全工作区616项测试通过，无忽略项；格式、禁止警告的Clippy与Rustdoc检查通过。

| 场景 | 结果 |
|---|---|
| 放置规划后普通移动提交，实体进入目标格 | 原计划与冻结后还原的计划都因Conflict拒绝 |
| 准备后可信宿主直接生成占用实体 | 发布在写入前报错，方块及附属实例均未出现 |
| 下半区域被占用 | 拒绝下半形状，允许上半形状；补全整块时重新拒绝 |
| 原子组内另一成员生成或移入目标格 | 整组拒绝，身份与单元无部分修改 |
| 原子组内生成位于其他格 | 普通实体和方块附属实例共同提交 |
| 条件错位、重复、超限或最终状态被覆盖 | 准备或解码拒绝 |
| 带条件的冻结任务 | 核对显式字节布局、往返、全部截断位置、预算失败和输出回滚 |
| 子进程在交互任务冻结后直接退出 | 重启后先执行移入，再拒绝冻结放置；再次重开保持拒绝结果和空单元 |

## 边界

普通实体仍使用行走体尺寸，本次没有建立通用实体碰撞体声明。检查使用事务结束时的位置，不表示实体间的连续碰撞求解。没有实体数据的低层准备入口拒绝空间条件；可信原生写格只有主动声明条件才执行占用复核。

没有空间条件的旧冻结任务继续按旧语义解释，不推断旧操作意图，也不调用动作处理器重新规划。宿主升级时须按自己的规则兼容要求处理这些未完成任务。进程测试验证直接退出及重开，没有验证硬件断电；本报告不作性能结论。
