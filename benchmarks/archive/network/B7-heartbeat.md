## 目标

修复[#12](https://github.com/TorseWorks/Torse/issues/12)。应用协议版本2，codec/wire版本1。

## 方法

### 行为

观察者订阅后没有请求时，原先约60秒就会触发空闲回收。现在客户端从Welcome开始每10秒发送无字段Ping，渲染帧和等待钩子共同驱动，最小化窗口也继续轮询。两次轮询使用同一计时状态，长时间暂停后只发送一次，不补发积压心跳。

服务端只在握手后接受Ping。逐帧接收时间更新沿用原路径，无回包、请求序号、执行状态或日志变化。握手前Ping立即关闭；客户端停止发送后仍按idle_ticks回收。默认时序为1200 * 50ms = 60s，满足至少三个10秒心跳间隔；真实时间宿主可调用NetworkLimits::validate_timing核对时序。

## 结果

### 自动验证

新增4项回归测试，全工作区638项通过，无忽略项。格式、Clippy警告视为错误及Rustdoc警告视为错误检查通过。

| 场景 | 结果 |
|---|---|
| idle_ticks设为3，观察者持续心跳跨越16个Tick | 订阅存活，没有回包，Ping前后提交游标和完整RuntimeState相同 |
| 同时连接静默客户端、之后停止观察者心跳 | 两者均按原空闲规则回收 |
| Ping后提交RequestSeq(1) | 正常接纳，心跳不消耗请求窗口 |
| 握手前Ping、协议版本1及未来版本 | 关闭对应连接，槽位可重新使用，世界游标不变 |
| Ping编码与非法帧 | 字节为01 00 05，未知标签、截断、尾随字节拒绝 |
| 客户端计时 | Welcome前不发送，10秒边界发送，同一时刻两次轮询只发一次，暂停后不补发 |
| 时序约束 | 30秒边界通过，较短窗口、零周期及计算溢出拒绝 |

服务端场景见[execution.rs](../../../apps/server/tests/execution.rs)，客户端计时见[net.rs](../../../apps/client/src/net.rs)。

### 默认配置实跑

使用独立文件世界启动服务端，客户端连接后保持静止且不编辑，随后最小化窗口，超过三个默认空闲窗口后关闭客户端并检查退出结果。运行命令如下，输出目录由调用方创建：

```powershell
target/debug/torse-server.exe .work/heartbeat/world --listen 127.0.0.1:17777 --ticks 4100 --fill
target/debug/torse-client.exe --window --connect 127.0.0.1:17777 --width 320 --height 240
```

实测客户端持续运行196607毫秒，其中最小化122秒；结束前进程仍存活，正常关闭后输出session=1、baseline_sections=2、requests_sent=0、requests_rejected=0，标准错误为空。持续时间超过三个60秒空闲窗口，最小化阶段也超过两个窗口。服务端按4100个Tick的上限正常结束。

### 兼容范围

旧客户端与新服务端、新客户端与旧服务端均在Hello版本检查时拒绝。现有消息标签保留，Ping追加为5。存档、执行记录与wire布局版本不变；不加入TLS、认证或关闭原因诊断接口。
