## 结果

### 范围

服务端可按持久玩家位置选择水平半径内的分区，按距离及坐标排序并截取有限窗口。候选来自宿主批准的PeerPolicy范围，自动跟随不会增加授权。

窗口改变时关闭旧复制ID，等待全部目标分区就绪，再发送新基线。多人窗口取有限并集驱动现有驻留调度；预算不足保留意向并重试。当前驻留玩家的分区独立固定，暂未绑定的玩家也保持可接入。

### 使用

```sh
cargo run -p torse-server -- .work/follow-world --fill --players 1 --follow-radius 1 --ticks 5 --listen 127.0.0.1:0
cargo run -p torse-server -- .work/follow-world --players 1 --follow-radius 1 --ticks 5 --listen 127.0.0.1:0
cargo test -p torse-server
cargo clippy -p torse-server --all-targets -- -D warnings
```

命令行示例仍是有限世界：每名玩家窗口最多4分区，共享驻留最多64分区，使用已保存页，不提供新地形生成器。通用宿主可配置自己的批准范围、复制上限及GenerationSource。重开世界时恢复已保存分区页索引。

### 验证

玩家回归测试用三分区世界验证窗口变化。初始窗口包含两个分区，远分区先保存并卸载；玩家从x=15.6开始，两次输入分别移动0.215格并确认到序号2。跨区后旧ID立即失效，第三分区重载后新基线包含三分区。反复轮询不增加移动，包络外订阅被拒绝，断线重连的移动确认从0开始。

独立测试验证多人兴趣并集、断线后移除意向、复制分类预算耗尽时无基线且连接保留、释放后建立基线、全部对象释放后逻辑内存归零。选择算法覆盖极端坐标和确定排序。

## 边界

跟随模式的Subscribe校验授权后保留宿主窗口；Unsubscribe释放当前复制，下次轮询重新建立。未启用跟随时保持原有手动订阅。

共享意向受4096项及驻留配置双重限制，超过容量保留上次已接纳意向。玩家与事件固定项也受总驻留容量限制。实际I/O仍由已有单作业调度器执行，拒绝不会扩大内存或重结算移动。半径和窗口应容纳宿主需要的碰撞邻区。

逻辑预算、有限世界功能测试与单机短跑不能代表跨设备帧率或长期流送性能。协议和存档版本保持不变。
