## 方法

### 能力

SnapshotArchive在原快照之外保存来源兼容信息、逐状态版本和组件所有者及版本。缺失内容的格、有限状态值、组件嵌套字段、实体ID及分配水位可以编码、检查和再次编码，检查报告列出不可用项。未知数据只保存在离线归档中；恢复活动世界仍要求全部内容可解析并通过领域约束。

MigrationPlan绑定精确来源兼容信息与目标兼容信息。组件迁移要求目标声明migration_binding、正确所有者和来源版本，回调输出再按目标模式验证。方块迁移逐个声明有限状态映射，同一类型未映射的其他状态仍保留旧版本。候选结果独立构造，失败不改变原归档。

ExecutionArchive保留执行状态。跨兼容版本迁移要求规则声明一致，且没有待执行事件或冻结任务。导入新文件世界还要求Tick起点，显式分配新的WorldId，提交序号从零开始；实体身份、水位和逻辑Tick保留，原会话结果窗口留在原归档中。目标文件目录使用现有新建流程，随后继续Tick和正常重开。

## 结果

### 验证

| 场景 | 结果 |
|---|---|
| 移除内容包、编码往返、重新装回 | 原始格与字段保留，缺失时拒绝激活，装回后可恢复 |
| 组件版本升级 | 字段显式转换，嵌套字段和其他模式保持，实体身份不变 |
| 缺处理器、错误所有者或版本、回调失败、非法输出、预算不足 | 返回错误，来源归档保持原值 |
| 旧快照无版本清单 | 报告MissingStamp，不从当前安装包推测历史版本 |
| 同一方块的多个有限状态 | 只映射一个时，另一个仍拒绝恢复；全部映射后通过 |
| 截断、错误魔数、解码预算和编码失败 | 拒绝非法输入，编码输出回滚 |
| 定时事件与冻结工作 | 归档往返保留，跨版本迁移拒绝，来源不受损 |
| 真实文件导出、迁移、导入与重开 | 关闭来源实例后比较全部文件字节，导入前后来源完全一致；目标继续Tick后重开成功 |

## 边界

### 使用边界

这是显式库接口，不是启动时自动修复或命令行迁移工具。普通检查点仍用既有格式。旧快照需要可信的原内容清单才能确定来源版本；回调为受信原生代码，不提供沙箱和自动版本链。关联的方块实例必须通过既有恢复配对检查，不会自动生成业务字段或分配新实体。持久分区流送另行实现。
