## 方法

### 实现

WorldAuthority::prepare_phase_advance生成没有世界变化的准备记录，元数据指向下一个完整阶段。准备不修改序号或进度，丢弃不消耗位置。发布同时检查原序号、观察到的恢复位置和兼容信息，全部满足后才推进。普通事务仍记录当前恢复位置。

Server::advance_phase复用日志预留、发布、接纳及刷盘流程。六个阶段依次前进，阶段5完成后Tick加1并回到阶段0，next_step固定为0。阶段或步骤非法、Tick溢出和提交序号耗尽均拒绝，不回绕。

进度记录使用空ChangeSet，不增加字段，世界写入格式继续为3，外层包裹为1。恢复只允许空记录推进恰好一个阶段。世界修改记录须保持进度，检查点须位于Tick起点。日志可以恢复到任一完整阶段边界，关闭时把剩余阶段逐条持久化，再保存下一Tick起点。

Windows、Rust1.93.1默认功能下，工作区376项测试通过。阶段专项新增7项，已有进程退出测试另增加进度记录的两个退出模式。

| 场景 | 结果 |
|---|---|
| 每阶段修改世界、持久推进并重开 | 六个阶段的完整世界与恢复位置均一致，最后到Tick1起点 |
| 丢弃准备及日志预算不足 | 序号、地形与进度均保持，重新打开后可以继续 |
| 准备后恢复位置改变 | 原准备的世界事务及进度记录均拒绝，未写入地形 |
| 阶段跳跃、倒退、未知阶段、非零步骤、修改世界同时推进 | 恢复拒绝，合法连续记录仍能恢复 |
| 从阶段1关闭 | 依次持久提交余下五个阶段，再发布Tick1检查点 |
| 关闭预算只够两步 | 返回ResourceLimit，已持久阶段3可重开并继续关闭 |
| 发布后接纳前直接退出 | 进度仍为旧持久前缀 |
| 持久确认后直接退出 | 恢复到已完成的新阶段 |
| Tick及提交序号耗尽 | 明确失败，未改变位置 |

## 边界

advance_phase要求可信调用方已完成当前阶段的工作。该接口提供持久阶段边界，没有接入Simulation的系统执行、阶段内任务游标、待执行事件、请求结果或去重窗口。关闭自动推进适用于当前没有排队任务的本地模型。完整M3继续保留后续验收。
