## 目标

### 一、问题与修改

字节编解码原先检查了排序和重复身份，直接传入Snapshot的恢复路径却会先转换字段。重复记录键可能在转成BTreeMap时被覆盖，Never组件也可能在结构校验前被投影掉；深层嵌套数据会先经过递归转换或克隆。

新增Snapshot::validate_structure，统一检查世界边长与高度、严格递增的状态和分区及实体身份、组件和字段顺序、嵌套记录键、Dense格数、格状态引用、身份水位与可索引的实体位置。空格标识不能在状态表重定义，所有非空格必须引用已登记的快照状态。

组件检查在转换与克隆前执行，沿用64个实例、4096个节点、64KiB保守载荷及8层嵌套限制。递归前检查深度，字段和值只借用遍历；状态引用使用固定8KiB位图检查。

## 方法

### 二、入口与兼容

| 入口 | 检查时机 |
|---|---|
| Snapshot::restore | 创建恢复状态和转换字段前 |
| Snapshot::persistent_view | 丢弃Never组件或克隆投影前 |
| SnapshotArchive | 归档检查和克隆前 |
| 编码 | 原有细粒度检查之后、提交输出之前 |
| 解码 | 有界解析后、交付快照之前 |

编码保留原有排序及资源限制错误，后续结构拒绝由Encoder回滚输出。直接恢复和字节解码都拒绝未定义状态，避免把损坏数据延迟到地形解析。

结构检查不解析已安装内容。合法但包含缺失模块内容的快照仍可离线归档，活动恢复继续按原规则拒绝。Uniform、Dense及旧版本兼容解码路径保持原格式，存档和网络版本均不变。过去会被合并或投影掉的非法重复字段现在拒绝，须从可信来源修正。

## 结果

### 三、验证结果

```sh
cargo test -p torse-world --test snapshot_validation --locked
cargo test -p torse-codec --test world_format --locked
cargo test -p torse-sim --test core_consistency --locked
cargo test --workspace --all-targets --locked
```

新增6项结构回归、2项字节边界回归和1项恢复回归。覆盖重复及乱序身份、组件和字段、嵌套键覆盖、非法格数与状态引用、无效范围与实体、过深及过量组件载荷、缺失内容保留、旧全同值Dense恢复，以及编码失败不残留输出。

恢复回归把重复字段放在Never组件中，确认投影前拒绝且恢复位置不变，同一恢复器随后可接受合法快照。原有格式固定字节、截断、资源错误分类及旧版本测试继续通过。

整合最新服务端主干后，Windows全工作区720项测试通过，零忽略；格式、Clippy、Rustdoc和mods编译通过。
