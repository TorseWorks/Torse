## 目标

ExecutionHost新增显式装卸入口，复用既有日志预留、发布、失效控制与持久确认。

## 方法

### 实现

Server::unload_section先捕获目标分区的持久投影，将页同步发布，再预留并提交卸载记录。Server::reload_section读取记录中指定的页，核对摘要、内容、身份及驻留状态后提交装载。Server::install_section接收可信生成的单分区页，新页不能引入实体身份。准备和发布阶段均不做文件I/O。

分区页带状态字典、格、实体字段及来源水位，以SHA-256摘要命名。页写入临时文件、同步后重命名，Unix再同步页目录。文件数及单页编码、解码预算有上限，已有页不覆盖。孤立页不进入世界索引，当前没有自动垃圾回收，容量不足返回ResourceLimit。

卸载后实体退出活动表，其ID和字段留在页中；全局分配水位保留，重装使用原ID，旧句柄保持失效，其他分区实体的句柄不变。Never组件不进入页。原生系统读到的是当前驻留对象；卸载不推进模拟时间。当前存在待执行事件时保守阻止卸载，避免把仍需执行的对象移出活动世界。

装卸要求空闲Tick边界，没有已接纳输入或冻结规划；票据仍阻止卸载。受影响的授权订阅走独立失效控制，清除已排队数据并断开对应Peer，重连获取新基线；不相交的Peer保持连接。重装推进地形修订，旧网格任务不能因修订重用而进入缓存。

## 结果

### 验证

新增11项专项测试，包括子进程测试入口。Windows全工作区649项测试、格式、Clippy、Rustdoc与mods特性编译均通过。

| 场景 | 结果 |
|---|---|
| 卸载日志尾、未驻留检查点、重装后日志尾 | 重开保持驻留结果、格、实体字段、ID和分配水位 |
| 新分区安装及拒绝覆盖 | 新格持久可读；已有分区或新实体身份输入拒绝 |
| 票据、放弃准备、旧句柄和地形修订 | 失败不推进提交，其他句柄保留，重装使旧依赖失效 |
| 授权Peer已排队旧基线 | 卸载先清队列并断开相交Peer，远端Peer保持，新连接取得完整基线 |
| 冻结工作和定时事件 | 拒绝卸载，执行状态及提交位置保持 |
| 页面损坏、丢失及预算 | 拒绝恢复或操作，不重写原日志，恢复正确页后可重开 |
| 日志预留受阻 | 驻留、身份和页索引不变，正常容量重开后可重试 |
| 真实进程在页发布后退出 | 孤立页不导致卸载，重开仍驻留 |
| 真实进程在卸载持久后退出 | 重开未驻留，重新装回不复用ID，二次重开一致 |
| 旧执行快照1、提交1和2 | 继续读取，默认空页索引及无装卸字段 |

测试见[streaming.rs](../../../apps/server/tests/streaming.rs)。

### 实跑

```powershell
cargo run -p torse-server --example durable_stream -- .work/stream-world park
cargo run -p torse-server --example durable_stream -- .work/stream-world load
cargo run -p torse-server --example durable_stream -- .work/stream-world grow
```

三次独立进程的输出如下：

```text
seq=13 tick=1 resident=1 parked=1 entities=0 next_entity=3
seq=26 tick=2 resident=2 parked=0 entities=2 next_entity=3
seq=39 tick=3 resident=3 parked=0 entities=2 next_entity=3
```

### 范围

这是显式库接口和文件示例。演示主程序继续使用固定范围，不自动按相机选区，不新增种子、生成规则版本迁移或异步I/O。驻留分区和未驻留索引各最多4096项，单页及完整索引同时受预算限制；页文件数量由SectionPages单独限制。未来事件保守固定驻留，尚不做逐事件分区依赖推导。

世界格式仍为3，网络应用协议仍为2，wire仍为1。ExecutionCodec写执行快照2和提交3，读取旧格式。重开含装卸历史的世界时，恢复器须用with_section_pages接入同一页目录。备份须保留日志、检查点和被引用的sections页；K03便携归档要求先装回全部未驻留分区，避免漏掉页数据。Windows文件同步继续沿用既有平台限制，未新增硬件断电保证。
