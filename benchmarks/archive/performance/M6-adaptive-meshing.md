## 方法

### 实现

FrameBudget根据已完成帧耗时调节后续生成、网格和地形上传数量。窗口目标16666微秒，各类每帧最多4个分区。超时立即降低数量，连续8帧低于目标四分之三后恢复一级，最低保留一项以继续推进。主机设定为零的类别保持禁用。

SectionUploadQueue合并重复分区意向，转换顶点前检查当前大小。每帧地形载荷最多8MiB，超量保留待传；单分区超过硬限明确报错。卸载移除意向，场景替换清空队列。实体及UI保留各自呈现路径，此硬限专指地形。

网格优化先判断完整不透明方块，再合并相同材质及着色的共面行。后续占用行实现与合并共用一份表，最多33KiB；准确大小由occupancy_scratch_bytes给出。覆盖层、半形体和透明面保留参考规则，缺失邻区保持可见。超过64格边长使用参考构建。新入口采用可按格重复的UV，客户端使用重复前导数选择LOD；build_mesh_reference保留未优化对照。

现有工作线程策略继续按可用并发减2并限制1到4，执行器仍限制8个任务、8MiB输入及32MiB工作输出。世界存档、内容身份和网络格式不变。

## 结果

### 验证

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo run --release --locked -p torse-render --example mesh_runs
cargo run --locked -p torse-client -- --capture .work/mesh.png --radius 1
cargo run --locked -p torse-client -- --window --frames 120 --radius 1 --autoplay
```

工作区860项测试通过，无失败和忽略。新增验证以半格精度比较参考和优化网格的表面覆盖、朝向、材质及着色，覆盖透明块、半形体、覆盖层、未加载边界和拒绝条件。单线程与四线程场景结果一致；同步视觉接纳同样遵守零项及一项预算。帧反馈覆盖突发负载与渐进恢复，上传队列覆盖按字节延后、重复合并和卸载。

Vulkan离屏生成9个分区、2203个四边面。窗口自动推进完成121帧、29次重建及上传、6次成功编辑，峰值6个CPU任务、2613200字节输入、26469056字节工作输出。贴图逐格重复，地形表面和选择轮廓正常。121帧包含退出截图前的最后一次呈现。

数据见[CPU测量](../data/adaptive-meshing/01-runs/mesh.csv)及[窗口测量](../data/adaptive-meshing/01-runs/window.csv)。16格完整立方体重复构建100次，比较如下。

|---|---|---|---|

载荷降为1/16；该简单CPU场景耗时改善有限，不据此推断所有地形都会加速。记录为单设备单次测量，未统计P99或GPU执行时间。反馈只能限制后续工作数量，不能保证一次大任务或GPU等待不超目标帧时。
