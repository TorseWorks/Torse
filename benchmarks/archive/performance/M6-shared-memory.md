## 目标

两端主程序复用同一个逻辑预留账户，将世界、网格、资源、复制、编码和CPU任务接到进程总量及分类上限。该记录验证预算语义，不将预留字节等同于进程常驻内存或GPU显存。

## 结果

### 接线与生命周期

MemoryPool持有共享账本，MemoryLease随拥有的数据移动，析构释放；分类转移、增量合并和失败恢复均保持总量原子校验。调用方在构造拥有的数据前预留，旧版本在新结果发布前继续计费。

服务端在恢复后、接纳连接前登记常驻世界、执行态、输入与会话控制空间及存储工作缓冲。准备提交先申请工作和世界增长空间，拒绝时留下冻结任务与输入，持久序号不推进。分区页I/O跨工作线程及交接期保留账额，完成、过期或失败后释放；运行中的I/O不能被预算驱逐。

复制按每订阅上限覆盖状态、缓存、基线及批次交叠；传输按有界队列容量保守预留，关闭时先释放缓冲容量再解除计费。网络中心持有一份串行复用的控制编解码空间，保证常驻账额满时仍可处理退订与关闭。订阅预算不足时最多保留一份请求重试，并重新检查当前授权。

客户端先为初始世界预留，再装配资源和CPU池。同步及后台网格共同参与预算，优先驱逐远处可重建网格，权威世界不参与驱逐。完成结果通过原预留转入网格分类，目的分类暂满时保留结果重试。基线或增量无法展开时丢弃旧场景显示，随后从最新授权镜像重建，避免内存压力下继续显示已撤权的旧数据。

图集副本由共享资源目录计费，共享调色板克隆不会重复登记。字形缓存及每帧画布、上传和截图的CPU工作空间也参与预算。解码事件离开连接后继续携带临时预留，直到调用方处理或丢弃。

### 验证范围

工作区820项、服务端mods配置193项测试通过，均为零失败、零忽略。格式检查、Clippy警告视为错误及七个相关crate的文档警告检查通过。

本地窗口出现34次CPU背压，工作继续完成；这不是吞吐或帧时延对照。截图在本地检查，未作为新资源发布。峰值取自实际程序汇总，按分类的峰值可能发生在不同时间，不能直接相加当作总峰值。

专项覆盖共享及并发上限、失败不泄漏、预留分类转移、任务取消、结果交接、资源卸载与重试、分区装卸、异步I/O、预验证缓存、满额关闭连接、缓存驱逐及解码暂停恢复。工作区、可选Mod配置与实际窗口运行结果保存在[原始记录](../data/shared-memory/01-assembled)。

预算服务约束受信适配器报告的逻辑容量。线程栈、分配器内部开销、第三方库私有分配、内核socket缓冲和GPU资源不属于这份账本，不能据此推导RSS上限。原生规则仍须遵守任务声明；Wasm单Store限制继续独立生效。资源预处理、大型内容包的完整预处理缓存及后续光照缓存另有相应装配工作。

## 复现

```sh
cargo test --workspace --all-targets --locked
cargo test -p torse-server --features mods --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo run -p torse-server -- .work/memory-world --listen 127.0.0.1:40123 --players 1 --ticks 180 --memory-mib 512
cargo run -p torse-client -- --window --connect 127.0.0.1:40123 --walk --autoplay --frames 180 --memory-mib 512
```

服务端与客户端默认各512MiB。`--memory-mib`调整各自进程的逻辑总上限；库调用方可用MemoryBudget设置不同分类上限，再将同一MemoryPool交给各适配器。小到无法容纳启动和控制空间的配置会明确拒绝启动。程序退出汇总包含当前、总峰值和按World、Mesh、Replica、Resource、Codec、Executor排序的分类峰值。
