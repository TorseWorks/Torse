# 按行占用位跳过满格内部面

日期：[20261028]
类型：测量
状态：已验收
环境：Windows、Rust 1.93.1、AMD Ryzen 7 7840H，release构建
范围：issue #3的CPU网格构建

## 目标

分区存档、网络布局和世界提交规则保持不变。合入当前主干时，占用表与既有共面行合并共用，保留顶点光照及AO；未合并逐面入口与完整参考入口均可独立验证。

## 方法

### 布局与语义

每个 `(y,z)` 行保存沿 x 轴的满格占用位：边长不超过32时用 `u32`，33到64时用 `u64`。只有具有完整立方体边界、非交叉形状且声明六面遮挡的格子进入这个快路径。半砖、植物、透明/部分遮挡形状继续使用原来的逐面判断；分区外邻居也按原采样结果处理，不假定已加载或不透明。采样器必须在一次构建期间描述同一份不可变视图。

对一整行，用移位计算 x 方向覆盖，与相邻行相交计算 y、z 方向覆盖。六个覆盖掩码的交集就是内部满格；遍历剩余位时使用 `trailing_zeros`，直接跳过内部区间。每行另有一个可绘制内容标记，已确认无几何的空行不再二次采样。输出仍按原先的 y、z、x、面顺序生成，材质、叠层、色调、法线和索引均保留。

临时载荷为 `side * side * word_bytes + ceil(side * side / 64) * 8` 字节：边长16为1056字节，32为4224字节，64为33280字节。零边长和大于64的边长不分配表，继续走参考路径。

### 共享预算与审查修正

原提交的默认入口为占用表单独建立私有账本，无法服从客户端的共享网格类限额。回归已复现：网格类限额为0时仍接纳一个后台网格任务。现在同步、后台客户端均在构建/复制输入前，通过共享内存池预留 `occupancy_scratch_bytes(side)`，归入不可驱逐的网格类。

后台租约随闭包进入队列并由工作线程持有，取消等待中的任务立即释放，运行中的任务直到实际退出才释放。任务工作/输出硬上限也纳入临时表大小；共享网格预留与执行器最坏工作量预留相互独立，整体记账保守。内存不足保留重建意向，记背压或留待下次刷新，不改世界内容。

公开的 `build_mesh`、`build_mesh_bounded` 不创建私有账本冒充共享预算；有总量限额的调用方必须按上述接口先预留临时空间。`build_mesh_accounted` 则为直接使用 `MemoryLedger` 的调用方管理同样的临时记账，在返回或失败时释放。

扫描最初仍逐格检查六个邻居，本次改为行级掩码和置位迭代。还补上空行标记，修正预扫描后再次采样全空分区的开销：32x32x32全空分区的采样次数由65536降到32768。

### 分支基线验证

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p torse-render --release --locked row_occupancy_cpu_comparison -- --ignored --nocapture
cargo run -p torse-client --locked -- --capture .work/row-occupancy.png --width 640 --height 400 --radius 1
```

渲染库启用GPU时37项测试、客户端97项测试，以及全工作区测试、Clippy与格式检查通过。另有1项CPU微基准默认忽略，已用上面的release命令独立执行。新增验证包括：

- 与关闭占用优化的参考路径比较完整 `MeshData`，覆盖边长0、1、3、32、33、64、65。
- 混合材质、逐面材质、叠层、双通道色调、半砖、植物、透明/部分遮挡、未加载及越界采样；包含负分区坐标。
- 32/64位行的左右端点，以及内部满格区间直接跳过。
- 全空分区只采样一次；预算拒绝发生在任务接纳前；排队网格取消释放共享临时空间；场景销毁后预算归零。

真实离屏检查使用debug构建、Vulkan、NVIDIA GeForce RTX 4050 Laptop GPU，无交换链呈现。640x400、半径1的场景输出9分区/9网格、29400顶点、44100索引、7350四边形；画面已检查。此项验证渲染接线，不作为帧时性能结论。

### 主干接入复核

占用预扫描同时服务逐面剔除和既有共面合并，不再额外建立第二份行表。保留face_shades，非均匀AO面仍使用逐面输出。客户端在复制输入前预留共享Mesh类空间，排队取消和完成均释放；build_mesh_reference提供完全关闭行优化及合并的对照。

147项客户端及渲染功能测试通过，计时用例默认忽略并已独立执行。当前设备复跑20次32格满立方体，参考耗时83508微秒，行优化23483微秒；全空场景为9288和3184微秒。采样次数与上表一致。复跑采用Windows、release及Rust1.93.1，仅计CPU耗时。

共面合并对照仍使用相同未优化参考，100次16格满立方体输出由1536个面、411648字节降至96个面、25728字节，耗时37704和34120微秒。前述原始测量保留为分支基线，当前数据见[data/row-occupancy/01-integrated](../data/row-occupancy/01-integrated/cpu.csv)。

## 结果

### 分支CPU微基准

环境为Windows、Rust 1.93.1、AMD Ryzen 7 7840H，release构建。两条路径使用同一合成采样器，输入和返回值经过 `black_box`，避免常量空采样器被折叠。每个场景连续构建20次32x32x32分区，比较原逐格/逐面参考与本次行位优化；采样次数为每次构建的计数。

| 场景 | 参考总耗时（微秒） | 优化总耗时（微秒） | 参考采样次数 | 优化采样次数 |
|---|---:|---:|---:|---:|
| 满立方体，外部未加载 | 94158 | 22453 | 229376 | 44680 |
| 全空分区 | 7877 | 3120 | 32768 | 32768 |

该实验是单机合成CPU微基准，没有GPU上传、呈现、真实资源查询或长期帧时分布。不能把这些数值当作客户端FPS提升比例或其他设备的时延承诺；混合内容仅验证几何一致性，尚未建立性能分布。
