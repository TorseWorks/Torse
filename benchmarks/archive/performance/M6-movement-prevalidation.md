### 二、移动预验证边界

简单块事务的前轮预验证实验没有收益。本轮先测碰撞较重的移动，再接入有界可选路径。支持范围为单成员、单次移动，且没有显式块前置、块写入、组件修改或生命周期操作。相邻任务必须修改不同实体；地形读集可以重叠，当前物理只处理地形碰撞。

ExecutionHost在冻结后、准备当前任务时检查连续窗口。默认关闭，CLI参数为`--prevalidate-workers 4`；默认最多4线程、16项、每项8MiB工作及输出预留。按扫掠包围体估算格数，小于512格或估计内存超过单项上限时走串行路径。格数估计包含边界余量，内存估计覆盖跟踪地形映射、见证向量、输出及固定临时空间；返回结果另按拥有的字节计费。该预算约束可信原生碰撞适配器，不是任意代码的分配器沙箱。

| 边界 | 行为 |
|---|---|
| 工作线程 | 借用同一世界和冻结表，只恢复稳定身份并执行原prepare_group，不修改世界或运行态 |
| 结果 | 不透明MovementPrevalidation，不能直接发布，不消耗提交序号 |
| 提交前 | 复核世界、兼容、阶段、所有碰撞查询、实体代数及精确前位置，随后绑定当前串行序号 |
| 发布 | 原publish仍再次核对见证，之后依次接纳日志、失效控制和刷盘 |
| 过期或失败 | 丢弃结果并回到原串行准备，原路径决定拒绝码与任务结算 |
| 重试 | 日志Busy保留预计算，命中统计包含准备后尚未发布的重试 |
| 释放 | 成功发布后释放对应项；阶段或冻结表变化时清空；恢复不读写缓存 |
| 不支持任务 | 截断窗口并串行准备，不跨块写入、组件或生命周期事务提前计算 |

缓存不进入日志、快照或协议。本轮继续使用提交载荷2、快照1、网络协议1和世界子体3，沿用既有恢复与DurableSeq输出门槛。独立规划的加入策略与此配置分开，现有Mod回调仍在宿主线程串行运行。

### 三、碰撞与完整路径测量

只读微基准对每项任务使用不同实体，起点为(14,8,8)，位移为(4,-4,0)，地面和分区相同。常规碰撞体半尺寸为(0.3,0.9,0.3)，大碰撞体为(4,4,4)。每组预热5轮，测20轮；结果向量逐项一致，微基准不发布任何准备项。

| 64项只读预验证 | 串行P50 | 1线程P50 | 4线程P50 |
|---|---:|---:|---:|
| 常规碰撞体 | 0.406ms | 0.454ms | 0.193ms |
| 大碰撞体 | 41.970ms | 42.283ms | 10.681ms |

完整路径使用真实Server、ExecutionHost、Journal编码及追加队列，以内存后端保存全部日志供逐字节比较，无磁盘同步。每Tick规划16或64项独立移动，X方向交替正负4，Y方向请求下降4；前两Tick落地后继续扫掠碰撞。每组预热5Tick，测20Tick，提交批量16，预验证窗口16，无复制订阅。

| 完整路径 | 串行P50 | 1线程P50 | 4线程P50 | 4线程P95 |
|---|---:|---:|---:|---:|
| 常规16项 | 0.272ms | 0.261ms | 0.244ms | 0.255ms |
| 常规64项 | 1.201ms | 1.199ms | 1.194ms | 1.269ms |
| 大碰撞体16项 | 7.499ms | 7.927ms | 2.459ms | 2.627ms |
| 大碰撞体64项 | 30.096ms | 31.231ms | 9.606ms | 10.127ms |

完整路径的常规碰撞体低于512格阈值，三种模式都走串行，差异只视为测量波动。大碰撞体64项的4线程约快3.1倍；1线程增加线程、缓存和复核开销。完整路径的碰撞位置与微基准不同，不能把两表视为同一任务的分项耗时。

串行、1和4线程的最终执行快照及完整日志字节相同。大碰撞体每组预计算25乘任务数个结果并全部命中，峰值16项，工作及输出预留128MiB，令牌拥有字节峰值539392，不含缓存容器与借用的冻结表。预留是保守上限，不是实际常驻内存；计数包含预热。CRC只供诊断，等价断言使用完整字节。

真实单机器Mod另使用仓库内machine包，输入库存64件，预热5Tick后测20Tick。无订阅的完整sink驱动均值0.139ms，规划0.048ms；8个授权订阅时驱动0.173ms、规划0.054ms、投影0.024ms。每组实际派发24次，输出6件、输入58件，没有陷阱或计划拒绝。这是单机器控制负载，未并行Guest，也不推算多机器收益。可选包加载器补齐InteractionProfile新增字段的空默认值，使mods功能继续编译。

### 四、验证与复跑

默认工作区561项、服务端mods特性110项测试通过，默认及mods特性Clippy零告警，格式检查通过。新增测试比较串行、1和4线程的完整文件日志、快照和授权复制；日志槽数2小于请求批量16，覆盖Busy重试。另覆盖重复实体、混合块写入、低预算、小碰撞体、无效配置，以及冻结后结算0/1/3/7项时恢复，禁止规划回调仍可完成剩余任务。内核测试逐项改变地形、卸载状态、实体代数、前位置、阶段与兼容信息，过期令牌全部拒绝且不消耗序号。

预验证、移动与复制专项重复10轮，共370次测试通过；CI增加预验证重复测试和CLI配置冒烟。

实际主程序用4线程配置创建至Tick 2，再以1线程及逐条提交重开至Tick 4，DurableSeq从24继续至48。该冒烟验证配置与恢复接线，并行负载由专项和上述完整路径基准验证。

```sh
cargo test --workspace --all-targets --locked
cargo test -p torse-server --features mods --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy -p torse-server --features mods --all-targets --locked -- -D warnings
cargo run --release -p torse-server --example serial_baseline --locked -- --output .work/projection-after --backend sink --ticks 30 --warmup 5 --batch 16
cargo run --release -p torse-server --example prevalidation_baseline --locked -- .work/collision.csv --movement
cargo run --release -p torse-server --example movement_baseline --locked -- .work/movement-pipeline
cargo run --release -p torse-server --features mods --example mod_baseline --locked -- .work/mod-baseline
```

输出路径必须不存在。Mod命令需要按[示例说明](../../../examples/mods/README.md)安装Wasm目标，构建和初始化不进入计时。原始数据中01/02为投影前后对照，03为只读碰撞，04为完整移动路径，05为真实单机器Mod。Gzip只包含本地生成的CSV，没有新增媒体素材。

本机数据不替代远端CI、硬件断电或大规模世界验收。一般事务的并行预验证、并行发布、异步刷盘和脏目标投影仍未实现。
