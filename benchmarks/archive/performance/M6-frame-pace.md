## 方法

### 最终接入

窗口沿用主线的`torse-render::FrameBudget`，生成、网格与上传份数硬上限分别为4，上传字节硬上限8MiB。反馈目标为16666微秒：慢帧降低接纳比例，连续8个低于目标四分之三的样本才恢复一档。非零份数至少保留1，字节硬上限保持不变，超限单份网格明确拒绝；失败上传保留重试意向。

当前反馈采样仍包括获取交换链图像及呈现可能产生的等待。本次增加阶段统计，没有将反馈改成只消费CPU工作时间。不要把诊断字段新增解释为已隔离垂直同步等待。

默认工人数取可用并行度减1，限制在1到64；执行器仍只允许8个在途任务，输入上限8MiB、工作与输出上限32MiB。共享执行器租约保持唯一记账，取消后的工作继续持有租约直到实际释放。同步内容包网格继续遵守每帧份数上限。

本次合并保留了主线的局部补面、分区边界及按变化输入筛选网格的实现，没有重新引入重复驻留过滤。

## 结果

### 汇总统计

| 字段 | 主机墙钟范围 |
|---|---|
| `cpu_us` | 生成接纳与网格刷新，不含逻辑步 |
| `upload_us` | 上传队列选择、几何准备、GPU提交及相关实体刷新 |
| `present_us` | 获取交换链图像、绘制编码及呈现 |

各字段按实际进入该阶段的次数取均值，未进入成功呈现的帧不计入`present_us`。它们不等于GPU执行完成时间。另有主线的每300帧阶段输出，两个统计用途不同。

### 验证

```sh
cargo test -p torse-client --features gpu-tests --locked
cargo test -p torse-render --locked frame_budget
cargo clippy -p torse-client --all-targets --features gpu-tests --locked -- -D warnings
```

与最新主线合并后的客户端156项测试通过，覆盖共享任务预留、拒绝不改世界、取消后释放、上传重试和同步分帧几何一致性。GPU回归继续覆盖补面、图集边缘及世界深度边框。历史帧预算算法的数值与旧窗口测量不再代表此合并后的实现，性能对照参见[大视距记录](../client/CLN-large-view.md)。

这些检查不证明所有设备上都能达到相同帧率，也不改变世界提交顺序、网络协议或存档格式。
