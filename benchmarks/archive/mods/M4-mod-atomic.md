# Mod机器原子持久执行

日期：[20261024]
类型：验收
状态：已验收
环境：Windows，Rust 1.93.1，文件日志与真实Wasm机器包
范围：B9接入A9的TransactionGroup，补齐机器、库存与事件的共同提交及恢复

## 目标

此记录不声明完整Mod平台、UI或硬件断电验收。

## 方法

### 一、实现

WorkPlan.transaction改为`Option<TransactionGroup>`，单事务构造器包装为单成员组。FrozenTask保存组身份和按来源排列的StoredTransaction成员；执行宿主按组准备，经原有日志预留、发布、接纳和刷盘返回持久结果。机器完成加工时，自有组件修改与plan_transfer生成的库存成员在同一提交中生效，新唤醒随同一条执行记录保存。

库存规划失败时整项机器计划丢弃，保留原进度和库存，不登记新唤醒。冻结后的前置条件过期或组件校验失败时整组拒绝，同样不应用成员修改和新唤醒。拒绝会消费当前事件，机器等待未来外部唤醒，不自动反复重试业务拒绝。

每次Guest派发使用新实例，规划重试不继承未提交Guest状态，诊断事务身份取持久事件身份。陷阱按事件载荷attempt重试，间隔8Tick，总计最多8次；最后一次消费事件且不登记后继，从而持久停机。ModStats为进程诊断计数，不作为业务状态保存。旧B8的待执行转移事件继续读取，新计划只创建普通唤醒。

冻结任务字段保留标签0和标签1，新增标签2保存组。单成员旧字节保持不变，旧日志可以继续恢复；旧二进制不能读取含新标签的任务。布局见[执行格式](../../../crates/codec/EXECUTION.md)。

## 结果

### 二、验收

| 场景 | 验证结果 |
|---|---|
| 加工中途恢复 | 进度3、输入1、输出0恢复后，一次任务变为进度0、输入0、输出1 |
| 共同提交 | 完成任务只接纳一条记录、推进一个提交序号，同时分配后续唤醒 |
| 库存争抢 | 两台机器共享一份原料，胜者完成，败者保持进度3，不产生后续唤醒 |
| 非法机器组件 | 库存成员合法但机器字段非法时，库存、进度和新唤醒全部不发布 |
| 日志容量拒绝 | Busy和TooLarge均保持完整世界、任务位置、提交序号和事件分配水位 |
| 刷盘失败 | 整组发布后注入同步失败，实例停止且禁止权威读取；文件重开恢复旧前缀，再完成整组 |
| 真实进程退出 | 加工中、组冻结后、发布后接纳前、刷盘后四处退出，恢复均为完整旧状态或完整新状态 |
| Guest重放 | 冻结组恢复结算和已结算日志重放均不派发Guest |
| 陷阱与隔离 | 陷阱后重启继续剩余尝试，总计8次；停机后重开不再派发，其他健康包正常执行 |
| 编码 | 旧单成员兼容、多成员往返、全部截断位置、条目预算、编码回滚及非法组拒绝 |

真实进程退出使用子进程exit直接结束，不经过服务端关闭或对象析构；退出码分别验证命中目标位置。刷盘失败在文件日志后端同步前注入，不能代替真实断电或磁盘设备故障测试。
